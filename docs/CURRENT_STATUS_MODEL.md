# CADAgent 현재 상태 모델

CADAgent는 CAD 연산과 그 연산이 구현·검증·관측되었는지에 관한 증거를 제공합니다.
서로 다른 종류의 사실을 하나의 막연한 “준비 완료” 상태로 합치지 않습니다.

## 용어

### 연산(Operation)

operation registry에 이름과 실행 제약이 등록된 하나의 CAD 작업입니다.
도구, 명령, 능력과 같은 말로 섞어 부르지 않습니다.

### 능력(Capability)

operation registry와 MCP 도구 선언에서 얻는 제품의 사실입니다. 현재 머신과 무관하게
CADAgent가 무엇을 선언하는지 설명합니다. 연산 레지스트리 검증은 정적 연산 어휘의
일치만 확인하며, 실제 디스패치 대상·핸들러 실행·의미적 성공은 증명하지 않습니다.
전체 상태나 준비 상태를 뜻하지 않습니다.

### 증명(Proof)

특정 능력이나 무결성 주장을 뒷받침하는 증거입니다. 정확한 소스 또는 배포 바이트에
결박되어야 합니다. 문맥 없는 `PASS`나 건강 상태와 구분합니다.
네이티브 배포 증명은 canonical 컴파일 입력과 아티팩트의 동일성을 확인하지만,
외부 ObjectARX·Visual Studio 도구 체계와 재빌드한 바이너리의 바이트 동등성은
증명하지 않습니다. 이 범위와 한계는 증명 항목의 최상단에 함께 표시합니다.

### 실행 관측(Runtime Observation)

특정 호스트를 특정 시점에 측정한 결과입니다. 관측한 소스와 배포 바이트, 시간 범위가
함께 있어야 합니다. 파일명에 `latest`가 붙었다는 이유로 현재 관측이 되지 않습니다.

### 기준점(Anchor)

소스에서 얻은 사실을 결박하는 정확한 저장소 revision과 checkout 조건입니다.
기준점이 없는 설치도 능력을 노출할 수 있지만 revision에 결박된 증명을 주장할 수는
없습니다.

### 역사 증거(Historical Evidence)

과거 주장이나 실행의 불변 기록입니다. 파일명, 날짜 또는 당시 판정만으로 현재 사실에
승격하지 않습니다.

## 판정 원칙

- 최상위 상태는 문서 조립 성공만 나타내며 하위 항목의 성공을 대신하지 않습니다.
- 기준점, 능력, 증명, 실행 관측, 역사 증거를 각각 판정합니다.
- 확인할 수 없는 것은 `UNKNOWN`, 계약을 만족하지 못한 것은 `BLOCKED`로 남깁니다.
- 서로 다른 revision이나 파일 세대에서 얻은 증거를 하나의 현재 상태로 합치지 않습니다.
- 역사 증거는 현재 증명의 대체물이 아닙니다.
