# HDC(현대_더에이치클라스트) 267도면 왕복검증 캠페인 — 봉인 보고서

## 결론 먼저

현대_더에이치클라스트(이하 HDC) 267개 도면 전체에 대해 `DWG → JSON(IR, 중간표현) → 복원 DWG → 재추출 JSON` 왕복(원본을 중간표현으로 뽑아냈다가 다시 도면으로 복원한 뒤, 그 복원본을 한 번 더 뽑아 원본과 대조하는 절차)을 수행한 결과, 182개 도면(68%)이 JSON 완전일치(엄격 PASS) 판정을 받았고, 나머지 도면도 평균 99.9854%의 엔티티 보존율을 기록했다(출처: #52). 이번 캠페인은 그 자체로 4건의 신규 결함(#49·#50·#51·#60)을 발견·수정했고, 병행 진행된 옥포동주상복합(이하 옥포) 16개 도면 검증에서 발견되어 같은 빌더/검증기 코드에 반영된 7건의 결함(#53~#59)도 HDC가 쓰는 파이프라인의 일부다. 이 보고서는 그 전체 지식을 이슈 스레드 바깥, repo 문서로 승격 보존한다.

이슈를 실제로 닫는 행위(코멘트 게시·상태 변경)는 이 문서의 범위가 아니다 — 코드 이식 레인들이 각 수정을 main에 머지·push한 뒤, 오케스트레이터와 Paul의 게이트를 거쳐야 한다. 이 문서와 `reports/issue_closures/`의 12건 초안은 그 게이트가 열렸을 때 바로 쓸 수 있는 판단 자료다.

## 1. 캠페인 개요

### 1.1 모집단

- **대상**: HDC 267개 도면 (출처: #52 제목 및 개요)
- **참고 비교군**: 워너청담 113개 도면 — HDC보다 먼저 검증되어 현재 파이프라인의 기반이 된 프로젝트 (출처: #52 결과 총괄 표)
- **병행 프로젝트**: 옥포동주상복합(옥포) 16개 도면 — HDC와 별도 모집단이지만, 여기서 찾은 결함 수정이 HDC와 동일한 빌더(`build_from_ir.py`/`build_awesome.py`)·검증기(`rt_compare.py`) 코드에 들어간다 (출처: #53·#55·#58·#59 각 도면 수 표기)

### 1.2 방법

1. 원본 DWG → 네이티브 추출기(`ARIADNE_NATIVE_JOB`, ObjectARX 기반)로 JSON(IR) 추출
2. IR → 빌더(`build_awesome.py`)로 DXF 재생성 → AutoCAD DXFIN으로 DWG 변환
3. 복원 DWG → 동일 추출기로 재추출 → JSON(IR')
4. 원본 IR과 IR'을 대조

적용된 파이프라인은 워너청담 검증에서 완성된 것으로, 추출 직렬화 락·DIMASSOC=0·`|` 심볼 정화·rc53(AutoCAD DXFIN이 반환하는 리턴코드 53, 파일 전체 거부를 뜻함) 인라인 폴백·WIPEOUT 레이어 수정을 포함한다 (출처: #52 개요).

### 1.3 검증 레벨 체계 (L1~L5)

#52 개요에 명시된 5개 레이어:

| 레벨 | 대조 대상 |
|---|---|
| L1 | 엔티티쌍 (원본·복원 엔티티가 종류·개수로 짝지어지는지) |
| L2 | 심볼테이블 (레이어·선종류·텍스트스타일·치수스타일·블록정의 등 이름 테이블) |
| L3 | extents (도면 전체 바운딩박스) |
| L4 | 콘텐츠 멀티셋 ((dxf타입, kind, layer, bbox) 키의 엔티티 내용 대조) |
| L5 | 시스템변수 (헤더 sysvar) |

엄격 PASS는 이 5개 레벨 전부가 JSON 완전일치할 때만 부여된다 (출처: #52 결과 총괄 "PASS (엄격 JSON 완전일치)").

## 2. 결과 총괄

출처: #52 "결과 총괄" 표.

| 지표 | HDC (267) | 참고: 워너청담 (113) |
|---|---|---|
| PASS (엄격 JSON 완전일치) | **182 (68%)** | 26 (23%) |
| FAIL (일부 불일치) | 70 | 87 |
| ERROR (검증 불가) | 15 | 0 |
| 엔티티 보존율 평균 | **99.9854%** | 99.59% |
| 보존율 중앙값 | 100% | 99.99% |
| 100% 보존 도면 | **187 (74%)** | 41 |

보존율 최저 98.713%, 검증 가능 252개(267-15 ERROR) 중 251개가 99% 이상 (출처: #52).

**데이터 정합성 메모**: #52의 "잔여 FAIL 분류 (70건)" 표는 하위 카테고리(49+11+9+1+1)를 합산하면 71이 되어, 표제의 70건과 1건 어긋난다. 이슈 본문 자체의 불일치이며 이 문서에서 임의로 재구성하지 않는다 — **UNKNOWN(미해소)**으로 남긴다.

## 3. 결함 분류

이번 캠페인(HDC 직접 + 병행 옥포)에서 확인된 12건을 결함 성격별로 분류한다. 각 항목은 §4의 이슈별 수리 기록과 1:1로 대응한다.

### 3.1 도면 전체 거부 (rc53급) — 불량 엔티티 1개가 파일 전체를 죽이는 패턴

- **#53** — periodic(닫힌) 스플라인 knot 벡터가 조용히 버려져 빈 knot → rc53
- **#54** — 대소문자 구분 비교로 실제 참조 중인 dimstyle `STANDARD`를 오삭제 → rc53

두 건 모두 이전 이슈 #46(ELLIPSE, 이번 12건 범위 밖)과 동일한 "불량 엔티티 1개 = 파일 전체 거부" 패턴이라고 이슈 본문이 스스로 명시한다 (출처: #53 root cause).

### 3.2 지배적 FAIL 원인

- **#49** — ezdxf `add_wipeout`이 `layer` 속성을 무시 → HDC 초기 FAIL 216건 중 214건의 지배 원인, ±14만 개 레이어 오배치
- **#51** — 블록내부 치수 상시 인라인이 INSERT를 연쇄 소실시키는 부작용 → 인라인 OFF 기본 + rc53 실패 시만 자동 인라인 폴백으로 설계 확정

### 3.3 데이터 소실류

- **#55** — 해치 경계 `ellipse_arc` edge 타입 불일치로 무시 + `major_axis`/`radius_ratio` 규약 불일치 → 해치 20개 경계 전체 소실
- **#56** — 빌더 dispatch에 `face3d`(AcDbFace) 분기 자체가 없어 3DFACE 136개 전량 손실
- **#58** — SHAPE 파일 STYLE 레코드가 이름 필터로 소실 + 이름 있는 shape 레코드 `STANDARD`가 대소문자 무구분 조회로 텍스트스타일 `Standard`의 폰트를 SYMBOL로 덮어씀 (오염)
- **#59** — LEADER가 `add_polyline3d`로 다운그레이드되어 개체성 소실(137→0, d014) + LWPOLYLINE의 Z가 `elevation` 필드 미반영으로 전량 유실
- **#60** — ezdxf 선생성 레이어 `Defpoints`의 케이싱이 원본 `DEFPOINTS`를 이겨 그 레이어의 모든 엔티티가 레이어명 불일치로 미매칭(HDC 재검증에서 POINT 7,326건)

### 3.4 오탐 (검증기 결함, 빌더/추출기 결함 아님)

- **#57** — 정렬 텍스트의 `insert`는 AutoCAD가 매번 재계산하는 파생 캐시값이며, 권위값은 `alignment_point`다. 검증기(`rt_compare.py`)가 `insert`로 비교해 생기던 오탐을 `alignment_point` 비교로 수정.

### 3.5 난제·외부 의존

- **#50** — ObjectARX 네이티브 추출기가 반포주공 PV계열 대형 도면(6.6~30MB, proxy 객체 포함)에서 Access Violation(0x0018 읽기)으로 크래시 → IR 추출 자체 불가. C++ 디버깅이 필요한 별도 과제이며 미해결.
- **#43** — OLE 임베드 복원. 이번 12건 봉인 범위에서 **제외**(Paul 지시, ADN 답변 대기) — §5에서 별도 취급.
